# 诊断信息的隐私边界

`bin/ime-diagnose` 用于排查安装问题，设计上**不读取、不输出用户输入内容或个人词条**。

## 会输出

- 环境事实：Python 版本、平台、架构、uid/euid、是否 root；
- 策略检查：前缀/数据目录是否被接受及拒绝原因；
- 安装状态：current/previous、版本列表、安装时间、文件数、大小、未完成事务、孤儿目录；
- 文件校验：当前版本逐文件 `sha256` 重算结果，只报告"漂移"的相对路径与原因；
- 运行依赖：按清单 `runtime.requires` 探测（`executable` 用 argv 数组 + 超时，
  `python-module` 用 `find_spec`，`file` 判断存在），记录状态与截断到 120 字符的输出行；
- 启动入口：链接路径、是否存在、是否受管、argv[0] 是否可执行；
- 运行数据：目录权限、文件数、总大小，以及每个文件的**相对路径、大小、模式、sha256**。

## 不会输出

- 任何词条、按键序列、候选、剪贴板或预编辑文本；
- 个人词库/学习数据文件的内容（只做哈希，不打印明文）；
- 环境变量值、命令行参数中的用户输入；
- 安装日志（`ime/install.log`）只记录操作、版本、相对路径、校验值与时间。

诊断报告首行固定包含声明："本报告不含任何输入文本或个人词条内容：仅包含路径、大小、
权限与校验值。"

## 自检如何验证

`tests/run_lifecycle_check.py` 的 `diagnose_privacy` 场景会：

1. 在 `personal/dict.json`、`learning/stats.json`、`settings.json` 中写入两个金丝雀串；
2. 运行 `ime-diagnose`（文本与 `--json`）、`ime-install list/verify`、`--repair`；
3. 断言金丝雀串不出现在任何输出中；
4. 扫描整个安装前缀（日志、状态、journal、备份、版本文件），断言没有个人数据副本；
5. 修改已安装文件制造漂移，断言诊断以退出码 5 报告漂移、仍不泄露内容，并在 `--repair`
   后恢复为健康状态（退出码 0）。
