旧入口保留原评分口径。新入口使用同样的最长参考前缀/最早排名贪心策略：每翻一页一次操作，显式选候选一次操作；数字可能是原文，因此用 select 表达选词动作，不能把插入数字当选词。原始逐次轨迹保留在各 *-quality.json 的 cost.trace，失败项成本为 null，仍计入全部 200 条分母；这不是用户认知成本或最优选词路径。

相对 0.3.0，新入口共同成功 169 条的操作均值 **1.4793 → 1.6036**；P95/P99 **6/8 → 7/11**。这是实际退化，原文选项和片段候选占用位置，分段重算也改变部分词语排序；保留为未解决项。

新入口相对 0.3.0：首选退化 0 条，前五退化 0 条，新增可完成 3 条，原可完成变失败 0 条。两个入口各独立进程重复 200 条结果及成本一致。

## 原慢调用逐条重放与阶段定位

输入清单直接来自 quality-revision/over-50ms.json，共 338 条，保留 profile、round、id、key_index 及历史值。按各原配置预热，重建前一个前缀后计时目标键；没有按新耗时筛选样本。原版源码快照及模型使用相同配置和种子。分阶段包装计时有少量开销，扩展总时间包含原生子阶段，不能相加。

原最慢调用约 1 秒，主要在 guess_candidates 的整串枚举。该阶段 P95 **173.6334 → 1.4327 ms**；整句 guess_sentence 阶段 P95 **67.7093 → 49.1789 ms**。

优化：整句 N-best 在解析末尾读取，避免纠错再枚举整串词语；全串原生前三保留，局部词语枚举限制为 24 码点；两条首音节约束用前两个音节取词，再约束全句；单编辑规则仍全部开放，按通用拼写先验最多解码四个读音。界限对所有输入相同，不包含质量语料或答案分支。原生调用不能中途取消，仍不是 50 ms 硬实时保证。

慢例集合经过历史筛选，不能当成全语料 P95。其 P95 超过 50 ms 的差距仍是未解决项；全部原始/复测/阶段样本可逐条审计。

## 检查与证据

运行 `python3 engine/tools/evaluate_mixed_revision.py` 与 `python3 engine/tools/report_mixed_revision.py`；构建/功能使用 README 的 CMake/CTest 入口。完整工作区证据位于 `engine/checks/mixed-revision/`：

- enhanced/composition/repeat*-quality-raw.jsonl、*-quality.json：原始候选、精确评分、逐次选词轨迹。
- quality-comparison.json、composition-comparison.json：基线和返工前的逐条变化与共同成功成本。
- *-keystrokes.jsonl、*-performance.json、*-cold.jsonl、summary.json：全部原始性能/内存及汇总。
- v030/current-tail-replay.jsonl、*-tail-summary.json：原 338 条慢例及阶段重放，无丢样本。
- composition-features.json、feature-matrix.json、revision-features.json、ctest.log：真实接口功能及 12 条逐键用例。
- immutable-before/after.json：原词库、音节表、冻结语料、0.1–0.3 包与历史证据散列不变。
- install-relocation.json、reproducibility.json、package-inspection.json：搬迁、重启、隐私和确定性打包。
- attempt-window-*、attempt-before-separator-fix/、composition-crash-localization.log：中间测量及已修复分隔符断言的原记录。

原 0.3.0 源码/文档在 v030-source/；历史 quality-revision/、enhancement/ 与旧包未修改。测试数据只用于检查，不被运行时作为词库载入。后续平台需接入 literal_digits 及新片段入口并验证真实应用；本报告证明引擎与端口行为。
